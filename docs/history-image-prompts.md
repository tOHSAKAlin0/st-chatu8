# 历史绘图提示词参考与云酒馆部署

实施日期：2026-09-12。基于 st-chatu8 2.8.4 分发代码。

## 这次增加的功能

普通聊天的「正文图片生成」可以读取此前楼层已经保存的绘图提示词，通过 `{{历史绘图提示词}}` 发送给绘图 LLM。它帮助延续 prompt 中已出现的人物外貌、衣着、场景和物件细节，不保存完整 Agent 回复，也不是自动视觉定义库。

在 **LLM → 上下文历史 → 参考历史绘图楼层数** 设置数量：默认 1，范围 0–20，0 关闭。计数单位是「有有效绘图记录的楼层」，与「发送历史层数」独立；中间无图的楼层会跳过。每个选中楼层发送全部有效图片提示词，按楼层先后顺序排列，同层重复提示词去重。

读取严格位于本次目标楼层之前的消息，不包含当前楼层和未来楼层。使用各消息当前 swipe 的记录。读取在请求开始时生成快照，随后异步处理不会重新读取另一个聊天的历史提示词。

### 接入新预设

1. 在插件 **LLM → 上下文预设** 导入 [novelai-v5-story-agent-history.json](../presets/novelai-v5-story-agent-history.json)。
2. 在 **请求类型配置 → 正文图片生成** 绑定 `NovelAI V5 · 剧情插图 Agent v3 · 历史提示词`，选择自己的文字 LLM API 配置。
3. 保持 NovelAI 模型和固定画风等原有生图设置，先将参考数量设为 1。
4. 触发正文生图，在 **组合提示词** 中检查历史区块以及诊断中的来源楼层、swipe 和图片数量。

新预设从实施时实际磁盘上的 v2 派生，保留最新的镜头、构图、具体人物位置、作品名称及动作/位置权重规则。新增历史复用规则和一组「同一人物脱外套后观察怀表」示例，共 17 条、4 组示例。原 v2 文件未修改，SHA-256 为 `dc9e312d5948479346c331d0df729cd65cd8645c9709150cd3e9142bb6a99655`。

使用自定义预设时，在实际资料条目中加入 `{{历史绘图提示词}}`，并说明相同对象沿用已有特征、明确改设和剧情状态变化仍然生效。没有这个变量的旧预设不会自动附加历史 prompt；变量为空时会移除占位符。

## 数据来源与边界

- 读取 `chat[楼层].extra.images[swipe_id]` 中的 tag，以及当前 `mes` 正文中用现行生图标记包裹的提示词。
- 保留场景、人物、权重和附属绘图字段；过滤思考回显、定位句、展示 HTML 和内嵌媒体数据。历史内容在变量执行结束后插入，不执行历史 prompt 内的 setvar 等宏。
- 如果用户修改的是楼层记录本身，会读取修改后的内容。但原插件图片编辑框的 `change` 可能仅保存在共享图片缓存中；本版不会读取这类改词，也不声称返回最终图片实际使用的全部后端参数。这样避免不同聊天对相同原始 prompt 的缓存修改互相影响。
- 无法关联楼层的前端卡/iframe `image_groups` 不在第一版读取范围。记录只存在这些位置时，诊断可能显示没有历史提示词。
- 没有有效历史、目标无法定位或历史读取异常时，照常生成；组合提示词诊断说明原因。
- 没有 prompt 描述过的细节不会被记住。减少引用层数可减少输入长度；本版不做摘要、对象检索或自动身份合并。
- 旧楼层重画不会读取后续楼层，但如果用户后来修改了较早楼层自己的记录，本版读取的是该记录现值，不提供历史版本回溯。消息编辑后的状态失效和完整分支版本管理仍属于未来方案。
- 这个设置不关闭原有「历史正文保留 image 标签」。两项同时启用时，旧标签可能也出现在正文历史中；使用新预设通常无需再开启旧选项。

## 本地验证

在插件目录执行：

```powershell
node --test tests/*.test.cjs
node --check index.js
```

测试抽取当前分发文件中的实际函数执行，覆盖历史范围、当前/未来排除、swipe、聊天隔离、正文标签、同层去重、自定义标记、异常记录、宏字面量保护、多模态消息保留、原预设哈希、新旧预设导入组装、XML 转换及角色提示词解析。另执行正文请求主函数，在正则测试模式检查最终组装和来源诊断。

这些验证使用宿主、日志、UI 和请求的测试替身；没有启动完整 SillyTavern，没有调用文字 LLM 或 NovelAI。不能据此认定实际图片已达到一致性要求。

2026-09-12 验证结果：10 组 Node 测试全部通过，`node --check index.js` 通过。另用 XML 解析器检查原 v2 的 3 份回复/5 张图/7 个人物栏，以及新 v3 的 4 份回复/6 张图/8 个人物栏，结构、单行叶子字段、定义 ID 和权重段检查通过。差异空白检查按现有 Windows CRLF 行尾约定通过。

## 上传 GitHub 与云酒馆安装

本修改版发布仓库：[https://github.com/tOHSAKAlin0/st-chatu8](https://github.com/tOHSAKAlin0/st-chatu8)。仓库根目录包含可直接安装的插件文件。云酒馆安装和实际出图验收需在你的酒馆中完成。

1. 先在云酒馆导出备份插件设置、文字 LLM 上下文预设及需要保留的聊天。确认平台允许从自定义 GitHub 仓库安装第三方扩展。
2. 本 GitHub 仓库已按扩展安装结构整理：`manifest.json` 与 `index.js` 直接位于仓库根目录。也可使用干净发布 ZIP 迁移到其他仓库，上传时不能多套一层文件夹。
3. 不上传整个本地工作目录中的 `.git` 或 `docs/evidence/`。发布 ZIP 已排除剧情实测材料，只带运行文件、预设、测试与本说明；保留原作者署名和许可证。
4. 在云酒馆扩展管理器使用 `https://github.com/tOHSAKAlin0/st-chatu8` 安装。目录名及插件标识保持 `st-chatu8`，不要让原版与修改版同时启用。若平台因同名安装冲突要求移除原版，先完成第 1 步备份，再按平台流程替换；不能保证所有云平台卸载时都保留设置。
5. 之后通过云酒馆扩展管理器更新，并确认安装来源是你的仓库。仅在原版上点击更新不会自动切换到你的仓库。
6. 刷新酒馆页面；必要时强制刷新缓存。以 LLM 设置中出现「参考历史绘图楼层数」为代码生效标志。R2 的 manifest 版本为 2.8.4-history.2，标题及 LLM 页面顶部显示「历史提示词版 R2」。仍未出现标识时，说明新界面尚未加载。
7. 单独导入并绑定上面的 v3 预设。更新插件文件不会自动替换已保存的用户预设。

**R2 更新说明：** 新增独立脚本入口和设置页面缓存刷新，资源路径跟随实际加载的插件位置；标题及 LLM 页面顶部新增版本标识。两处远程版本检查和重装地址已指向 tOHSAKAlin0/st-chatu8。实际更新仍调用酒馆的扩展更新接口，Git 来源由云端已安装仓库决定。保留原插件设置和预设，未增加存储迁移。基础验证共 13 项测试及两个脚本语法检查通过；尚未在用户云酒馆完成验证。

回退时可先将参考数量设为 0 或切回 v2 预设；若要回退代码，使用自己的仓库上一版本或备份，刷新页面后验证。新增功能没有引入聊天存储迁移。
